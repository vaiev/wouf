# Skill: <name>

A skill is a short recipe a member loads only when a step needs it. Copy this file to `team/skills/<name>.md` for a skill your team writes itself, add a header, and list it in `team/tools.md`.

```yaml
---
name: weekly-invoice-digest
status: proposed        # proposed | trial | active | retired
owner: lead
purpose: one line — when this skill is used and when it is done
---
```

## When to use

Trigger conditions, and when not to use it.

## Required inputs and access

What must be given or connected. The approval boundary for this skill.

## Sequence of work

Numbered steps, with what to do when a step fails.

## How to validate the result

Checkable conditions. What "done" looks like.

## What to return

The output and where it lands (board, file, return block).

## What requires approval

The actions that stop and wait for the human.
