All notable changes to WOUF are recorded in this file. The format follows Keep a Changelog.

## [Unreleased]

## [0.2.0] - 2026-11-12

The second release; it follows 0.1.0 and has no upgrade step (`.agents/upgrade/0.2.0.md`). `.agents/team/config.ini` is kept as it is, and the upgrade never touches bot storages or logins. Three things change without a config edit: task classification (`team goal` and `project brief` take their class from `teamlib.classify`; see Fixed), the tier label `mid->strong` (see Changed) and the lead's guard (see Fixed). The keys new here are optional and do nothing until you set them: `[runner.*] usage`, `[runner.*] login_paths`, `[class.<name>]` sections, `[egress] private`, `[classify] security_words` and `[classify] keywords.<name>`.

### Added

- `NOTICE`: the attribution notice of Apache-2.0 section 4(d). A redistribution of WOUF, or a work built on it, carries it, so VAIEV and WOUF stay named.
- Change receipts v1 (`docs/RECEIPTS.md`): `team receipt make TASK --reviewed H --landed L [--pr N]` builds the receipt of one landed change from the team's own records (`--dry-run` prints the unsigned body), signs it with `[federation] signing_key` and stores it as `team/receipts/<L>.json` and, the same bytes, as a git note in `refs/notes/wouf-receipts` on the landed commit, with a `receipt.signed` event that holds its sha256. `team receipt resign SHA` signs a stored receipt again with the current key; only `resigned_at` is new. The format and signature are in `teamlib/receipt.py`.
- The fingerprint of the key that signs WOUF's own receipts is `SHA256:kQfxHJ5w0JRzMT4JIburS5E0zGHlwk47+Zvauk5Ac1w` (key type ED25519); another team's receipts have that team's own key. It is published in this repository (`docs/RECEIPTS.md`, the README) and on wouf.dev. Those copies come from the repository, so compare it with a second copy, for example the release note of the tag, and with the key fingerprint `team verify` prints, before you trust a receipt.
- `[runner.X] login_paths`: the files and folders of a runner's sign-in (relative to HOME, space-separated) that a boxed run copies from `/bot/login/<path>` into its own HOME before the CLI, for a runner with `auth = login`. In this version a run does that only when the bot's own storage holds the path at `/bot/login` (no run mounts a separate login storage), a link is skipped and never followed, and nothing is copied back after the run. `.agents/team/config.ini` ships it commented out for agy.
- Runner usage contract (#136, `teamlib/usage.py`): `[runner.X] usage` says how a boxed run reports its tokens, so the budget (`[budget]`) and `team stats` also count runners other than Claude Code. The value is `builtin:claude` (shipped for `[runner.claude]`; read from Claude Code's own session records) or a shell command that runs in the sandbox after the CLI, at most 60 seconds, and writes `out/usage.json` (schema `wouf.usage.v1`: the tokens `input`, `cache_read`, `cache_write`, `output`, and optionally `seconds`, `unknown_runs` and `runs`). A run's `out/usage.json` is read first for every runner, then the `builtin:claude` line, else the numbers are unknown, as they are for every host run; `result.json` records `usage`, `usage_source` (`file`, `adapter` or `none`) and, for a file that is not the schema, `usage_error`. A runner without `usage` behaves as before: Claude Code gets the builtin, every other CLI reports unknown.
- Flow evidence for receipts (R2, R2.1): every flow step and `gate.json` keep their evidence (for a bot step its commit, model, CLI, tokens and egress summary; for a gate step its base, network, exit code, command hash and complexity), a bot step that never ran gets `unknown` evidence, and an egress log is kept as its sha256.
- Add offline verification of receipts v1, including signature, commit binding, and record consistency.
- Export stored receipts as deterministic in-toto Statements.
- `team demo` ends with a receipt step: it makes a receipt for the approved change with `team receipt make`, signs it with a throwaway ed25519 key in its temp folder, verifies it offline with `team verify` and shows a tampered copy refused (skipped without `ssh-keygen`).
- `team flow TASK --close --reason TEXT`: an end event for a flow that landed another way. Nothing is deleted; `team context` and `team status` hide closed flows, and the snapshot shows them as closed.
- Task classes from the config: besides the seven built-in classes, every `[class.<name>]` section with a `tier` in `config.ini` defines a class (a lowercase name of letters, digits and `-`) that every class check accepts, with `[classify] keywords.<name>` for the classifiers; `team doctor` names a section whose name is not one.
- `[egress] private = host:port[, host:port]`: a narrow, explicit exception to "public addresses only", for a model server on your own computer. Each entry is a literal loopback or private address or the container host alias and exactly one port; the proxy lets exactly those pairs through (every method, as a model API needs) and keeps refusing every other private address; a name, wildcard, range, network or public address refuses the run at start; a run that uses the exception says so at start. Empty by default. The bot's own-loopback exception of 0.1.0 stays fixed in code.
- Steps per class: `[class.<name>] steps` sets a class's flow as a table, `preflight* worker [gate review[*N]]` (e.g. `steps = worker gate review*2`), winning over `scout` and `reviews`; `rounds` sets the review rounds with CHANGES before a flow is blocked (default 2). The built-in classes keep their steps; `team flow` walks the table.
- `scripts/mdlint.py`: a standard-library check of the markdownlint rules bots break most (MD009, MD010, MD012, MD022, MD031, MD032, MD047, as configured in `.markdownlint-cli2.yaml`), run by `scripts/pre-gate.sh` before the test suite, so a host without node catches them before review.
- `team task class T CLASS`: gives a task made before task classes existed (no class in the store) its class, once, so `team receipt need` and the stats see it. Refused for an unknown task, a task that already has a class, an unknown class and a class that requires fewer reviews than `standard`, the class the store assumes for a classless task. It writes a `task.created` event with only the class, as `team state import` writes a rename; no store format changes.
- A completeness gate for a change in packages (T-0189): a brief's line `Series: NAME K/N` (NAME a task id, 1 <= K <= N <= 20) makes `team gate` red for package K < N on a base on main (`[gate] main`, default `main`; a base commit on that branch counts), and red for package N/N there unless its diff holds the migration `.agents/upgrade/<VERSION>.md` (VERSION unchanged: or the brief's `Migration: none REASON`) and an upgrade test `tests/test_upgrade_*.py`, which the gate runs itself on the head after a green suite. A malformed or second Series line is red. `gate.json` keeps `series`, `migration` and `upgrade_test`; a brief without a Series line gates as before. `team gate --help` names both lines. Code: `teamlib/gate_series.py`.
- Known gaps, fixed in 0.2.1: an upgrade test whose only tests are expected failures counts as green; upgrade test names with a dash or an empty version part (for example `tests/test_upgrade_0-3-0.py`) are refused; a zero-padded series number such as `001/002` is refused.
- The lead's write boundary, `[guard] lead_mode = on` (off by default) with `[guard] lead_write`, `lead_run` and `lead_env`: `.agents/bin/guard` checks the lead's own tool calls against an allowlist when the tool is called, also inside the project, and refuses with a reason that names the path or the command and says "brief a bot". A file tool may write only lead_write and `write_roots` (a relative path resolved against the hook payload's `cwd`, then `..` and symlinks). A shell line is allowed only when every simple command in it matches a listed shape with only the listed options (readers, `sed -n`, `sort`, `find`, `cd ./DIR`, `mkdir`, `cp`, `mv`, git's reads, `git add` and `git commit` of lead_write files, gh's reads, the pack's `team`, `log` and `federate`, a lead_run script, `NAME=VALUE` for a lead_env name other than those of `ENV_RUNS` such as `HOME`, `PATH` or `GIT_*`, its value `$(pass show ENTRY)` or a short literal that cannot name a path; a redirection only to `/dev/null` or lead_write; no word the shell expands in `uniq`, `sed` or a path the guard checks); a construct it does not parse (`eval`, `bash -c`, `$(...)`, loops, functions, `xargs`, `exec`, a heredoc to a command not listed or with a `$` or a backtick in its delimiter) is "cannot tell where this writes", anything else "not on the lead's list: brief a bot". The session should not be able to switch it off, with the known gaps of the next entry: the team's `config.ini` and `guard-deny.txt`, `.agents/bin/guard*` and the CLIs' settings files stay refused. It is a tripwire, not a sandbox: lead_run scripts and the pack's tools run unseen (`docs/DESIGN.md`, section 10). Wiring the hook on a host is a separate step.
- Known gaps of the lead's guard, crafted bypasses recorded for 0.2.1: a `cd` with a redirection that fails is still taken as run; a `cd` through `..` after a folder that does not exist (or a file) is still taken as run; bash follows a folder symlink logically and the guard physically, so a `cd ..` after one can end elsewhere (`docs/DESIGN.md`, section 10, "Known gaps (0.2.0)").

### Fixed

- The suite no longer writes outside its own temporary folders whatever `WOUF_*` the caller has: `test_budget`, `test_run_usage` and `test_usage` ran teamlib in-process with only `WOUF_TEAM_DIR` patched, so in a bot sandbox (`WOUF_LOG_DIR=/bot/logs`, since #168) they failed and appended fake lead receipts to the real log folder, and 15 more modules (`test_session` with a caller's `WOUF_MASK`, `test_goal`, `test_receipt_build`, and others) failed or wrote there too. The suite runner `scripts/test-parallel.py` drops every inherited `WOUF_*` variable (all but `WOUF_TEST_TIME_FACTOR`, which only stretches the tests' waits) before it starts a suite, and the helper `tests/support.py` (`wouf_env()`, `isolate_wouf_env()`) does the same inside a test module. Not every module is proven to be clean: the four modules that call the helper in process (`test_budget`, `test_meta`, `test_run_usage`, `test_usage`) are checked by a guard test that runs them with the log, events, team and state folders on one empty folder and checks it stays empty, and the guard test also checks that every module that uses the helper calls `isolate_wouf_env()` in its `setUpModule`.
- The fake podman in `tests/test_gate_cache.py` reads stdin only for `run` (the call that gets the bundle), not for the gate's other engine calls, which inherit the caller's stdin: the test no longer hangs when stdin stays open. `scripts/test-parallel.py` gives every suite `stdin=DEVNULL`, so no test can wait on the caller's terminal or an open pipe.
- `bin/log` and `bin/team` use one folder rule for log lines (`WOUF_LOG_DIR` when set, else the team's `logs`): run by
  hand on a team outside the pack, `log task` read the pack's own folder and printed nothing. `log task TASK` now also
  lists its fix rounds `TASK-fixN`, their review rounds `.rN`, run and flow events and gate records;
  `team result gate TASK` reports the saved gate instead of "no run", on one line with keys masked; it exits 0
  only for a whole green record (head, base, start, end and a code key, 0 or null).
- New task and goal IDs preserve existing zero padding.
- The lead's guard catches force pushes and deletes of main after git's global options (`-C`, `-c`, `--git-dir` and the like), as `+refspec`, `:main`, `--delete` and `--mirror`, and `rm -rf` of `$HOME` in its quoted forms.
- `team receipt make` no longer takes a closed flow as evidence: a task the lead drove by hand after its flow closed builds its receipt from `gate.json` (gate and `change.base`) and the run events, as without a flow, instead of being refused because the closed flow's old base is not the landed commit's parent.
- `bin/project` is a shim over teamlib: `project brief` takes its class from `teamlib.classify` (new `class_of`, and `[classify] security_words`, by default bin/project's former list, read in the goal and its path names, making a goal security in `team goal` too, also when `security_globs` is set and past the goal's first 2000 characters) and `project check`/`phase`/`deps` use `teamlib.goal`, so the two classifiers and brief checks can no longer disagree. No goal requires fewer reviews than the stricter of the two did: bin/project's former stems (also when `security_words` is set) and class words, and teamlib's former path class (a config may give `plan` more reviews than `security`), are a floor, so a design, compare or research goal, one over three areas or one without paths gets `standard` (or `complex`) instead of a class without review.
- The local-runner tool's `block` prints an empty `auth =` instead of `auth = none`, which the pack would read as a secret name.
- `team task start|working|review|done|todo T --reason TEXT` is accepted like `block --reason` (the board's reason column shows it), `done` answers the task's open questions with "task T done" in the same transaction (a write cut short is seen whole and finished by the next state command), `team run --repo PATH[@REF]` reads a relative PATH such as `ref/wouf@main`, `ref/wouf` or `wouf@main` from the caller's folder and names its absolute path when it is missing, and `team run --input` refuses a file in the task's own `out/`, which the run empties, before anything is deleted.
- `team context --claude` holds its payload to `BYTE_BUDGET` (16 KiB) of JSON: a non-ASCII character counts as the escape JSON writes for it, so emoji in questions no longer pass the budget (36,900 bytes before). The last line always counts the rows left out (`N more rows: team/board.md`), even when the questions fill the limit; it used to be cut away.

### Changed

- A runner without a `mid` model runs the `mid` tier on `strong`; the log and receipts now write that as `mid->strong` (ASCII `->`), where 0.1.0 wrote `mid→strong`. A receipt with the `→` form is refused (`FAIL form`).
- The worker role says which trailer to use when the brief forbids trailers (the brief wins) and which outcome to log at the end (`done` for ready-for-review, `blocked` for blocked).
- `team context` keeps its limit of 4000 characters but now spends it on what a session needs first: for a team in the store, the questions and the flows not finished stay, the newest open rows fill what is left, and the last line counts the older ones (`N more rows: team/board.md`). It used to keep the oldest rows and cut the questions first. A team without events does the same from `board.md` and the flows' state files, with the rows ordered by task number (T-2 < T-10 < T-200) whatever the order of the file.

### Tests

- The drift's cause claims as offline regression tests (T-0190): `test_drift_handover` (`team context` lists exactly the open rows, the open question and the unfinished flow, reports a hand-edited `board.md`, changes no state), `test_drift_fresh_env` (the boot's entry points find the project's own team and log folders with no inherited `WOUF_*`; `test_verify`, `test_receipt_export`, `test_guard`, `test_project_phases` and `test_bwrap_gate` run directly under a hostile `WOUF_*`, and no child they start, a `bwrap` included, gets a caller `WOUF_*` while no file is left in the decoy folders those variables named and no Python-level open for writing into a decoy happens (a recorder in every Python they start notes such an open, and a snapshot of the temp tree shows what is left; a write by a non-Python child that is removed before the run ends, or a write anywhere else, is not proved, both need an OS sandbox), with a fake `bwrap` on `PATH` so a host with bubblewrap runs the same; `test_bwrap_gate` asks `bwrap_usable()` after the module's isolation, not at import: they now call `isolate_wouf_env()`, the first three with `secret_store=True` so a run no longer creates `~/.config/wouf/secrets`) and `test_drift_context_limit` (200 rows, 50 questions and 50 flows stay inside the budget and say what was left out).

### Not in this version

- Receipts are made by the lead's command, `team receipt make` after a landing (`skills/review-merge.md`), not by themselves; a team without `[federation] signing_key` makes none.
- A receipt shows what the team recorded and signed, not that the code is right, that a model was honest or that a reviewer read every line. The signer is trusted: a compromised lead can sign anything. There is no independent witness or transparency log, and a team may withhold a receipt. It does not prove that the commit is on a repository's main branch.
- No WOUF command publishes the reviewed commit: after a squash merge a clone of main alone verifies a receipt only as `partial` (exit 3). `team verify` and `team receipt make` never push or fetch.
- WOUF does not sign the in-toto Statement. Token counts, gate complexity and egress records come from the team's own records and sandbox, and the signature time from the signer's clock.

## [0.1.0] - 2026-11-06

The first release. This section records what it contains. The commands, sandboxing and checks below are implemented and covered by the test suite; tests that need Docker, Podman or a working bubblewrap run only where those are available. The rules, roles and skills in the pack are instructions to the models: the tests check that their text and structure are in place, not that a model follows them, and they are not enforced by code.

### Added

- The pack in `.agents/`: rules every member follows, the roles lead, worker, review, decide and specialist, the skills the lead loads for a step, and the team layer with settings, core bots, board, decisions, schedule, knowledge and logs.
- Setup through the agent CLI the human already uses: `INSTALL.md` adds a line to `AGENTS.md` and the adapters Claude Code and Gemini CLI need, and outside the folder touches only the human's secret store and software the human agrees to install.
- `team run` in three modes: `container` with Docker or Podman, locally or on a VM through an SSH alias; `bwrap` for Linux without a container engine; and `host` without a sandbox, for trying things out.
- Container hardening: no capabilities, no new privileges, a process limit, CPU and memory limits, the bot's own storage as the only volume, and results copied back as plain files with links skipped.
- `mode = bwrap`: a bubblewrap sandbox per run with its own namespaces, no capabilities, no host environment, its own folders plus read-only host program folders (`/usr`, `/bin`, `/lib` and the like) and a fixed list of `/etc` entries, nothing of the home folder or project, a team prefix that stands in for the image, the bot lifecycle and `team gate` in the sandbox. CPU, memory and process limits come from a systemd user scope where one works; without it a run warns and goes ahead without them. It refuses `network = bridge` and says at every start what it lacks compared with a container.
- `network = egress`: an allowlist proxy for each run, with the bot on an internal network in container mode or without any network in bwrap mode. Each run gets the base list and only its own CLI's model hosts; a brief's extra hosts need the lead's recorded yes. Old Docker and Podman versions with a known name-resolution leak are refused.
- `team flow`: worker, a pre-gate without any model that checks the brief's paths and runs the tests without keys, in a sandbox in container and `bwrap` mode and in a throwaway clone in `host` mode, review and up to two rounds of rework. It ends `ready` only with an approval that names the head commit, by its full id or a prefix of at least 7 characters.
- Task classes from `mechanical` to `security`, `decision`, `analysis` and `plan`, which choose the bot, the tier and the number of reviews; the tiers `strong`, `mid` and `light`; runners for several agent CLIs; and one fallback runner when a usage limit is hit.
- Independent steps at the same time: scout and research, two reviews, and `team batch` for one plan wave: packages whose paths are pairwise disjoint run at the same time, each on its own worker, and an overlap starts nothing.
- `team goal` with the four phases INIT, CONCEPT, REALIZE and VERIFY, and a model-free classifier that proposes the class, paths and threat model.
- `.agents/bin/secret`: keys typed by the human in their own terminal, no command that prints a value, keys handed to a bot for one run on its standard input, and masking of registered values and key patterns in output, results, logs and receipts.
- An append-only event log with a rebuildable SQLite projection; the board and decisions are its readable export.
- Token caps per run, per day and per bot in `[budget]`, and an end date for a bot.
- A context graph of the brief's paths for complex and security briefs.
- `.agents/bin/federate`: signed envelopes between teams over a git mailbox, with incoming data kept in quarantine.
- `team demo`: an offline demonstration with a fake agent of the gate and the exact-head approval.
- `team update`: a preflight that lists the changes, an upgrade path from the installed version to the target, a backup before every apply, rollback with `--rollback` and `--list-backups`, and `team --version`.
- `team update --bots`: in container mode, a preview of a team image rebuild when its recipe changed; with `--yes` it builds the new image, puts it in use only after a successful build while no bot task runs (`--wait` waits, nothing is stopped), and checks each active bot's login read-only. Bot storages, logins and keys stay.

### Changed

- A dropped SSH connection to the engine's host no longer loses a run's result, and a host that stays away ends the run naming the lost connection.
- A warm container run takes at most three round trips to the engine's host.
- In egress runs, the bot reaches its own loopback directly; this exception is fixed in code and cannot be widened by the config or a brief.
- Each egress run gets only its own runner's model hosts instead of every runner's.
- A locked secret store now ends fast with one line instead of waiting.
- `team demo` brings its own minimal config and ignores the project's.

### Not in this version

Planned, not implemented: a key proxy for egress runs, so that keys no longer reach the bot itself.
